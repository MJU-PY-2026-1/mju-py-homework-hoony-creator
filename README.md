# 🐍 [2026-01] 나만의 파이썬 소프트웨어 개발 프로젝트

## 1. 시나리오 제목
* 프로젝트 볼트(Project Vault): 장기 프로젝트·포트폴리오 통합 관리 시스템
<br>


## 2. 시나리오 (5~10줄)
* 이 프로그램은 사용자가 진행 중인 장기 프로젝트를 기록하고 생기는 링크, 파일, 메모, 결과물을 함께 정리할 수 있는 개인용 관리 소프트웨어 입니다.
* 가장 먼저 프로젝트 이름, 분야, 최종 목표, 현재 진행률, 중요도, 보유한 자료 개수 같은 기본 정보를 입력하여 하나의 프로젝트 카드를 생성합니다. 시스템은 입력된 값들을 바탕으로 해당 프로젝트의 초기 준비도와 우선순위를 계산하여, 지금 당장 관리가 필요한 프로젝트가 무엇인지 보여줍니다. 이후 사용자는 프로젝트와 관련된 발표 자료 링크, 코드 저장소 주소, 참고 문서, 회고 메모 등을 계속 추가하여 하나의 포트폴리오처럼 정리할 수 있습니다. 프로젝트가 진행될수록 수행 과정과 결과물이 함께 누적되기 때문에, 단순히 할 일을 적는 것이 아니라 내가 무엇을 해왔고 무엇이 부족한지를 한눈에 파악할 수 있습니다. 나중에는 여러 개의 프로젝트를 리스트로 저장하고, 조건문을 이용해 프로젝트 상태를 ‘순항’, ‘정체’, ‘위험’ 등으로 판정할 예정입니다. 최종적으로는 메뉴를 통해 프로젝트 등록, 자료 추가, 상태 확인, 전체 조회, 포트폴리오 요약 출력까지 할 수 있는 실용적인 통합 관리 소프트웨어로 완성할 계획입니다.

<br>

5. 프로젝트 상태 확인
6. 전체 프로젝트 정보 출력

    * **적용 내용:** AI와 논의한 결과, ‘진행 관리’와 ‘결과물 저장’을 분리하는 것보다 하나의 시스템으로 합치는 것이 실제 활용도가 높다고 판단하였다. 그래서 단순한 할 일 관리 프로그램이 아니라, 장기 프로젝트의 진행 상황과 포트폴리오 자료를 함께 관리하는 ‘프로젝트 볼트’ 컨셉을 최종 주제로 채택하였다.
      
 2. **내용 2 : 확장 로드맵**
    * **프롬프트 요약:** “지금처럼 단순한 계획만 하는게아니라 자세하게 프로그램 개요가 어떻고 어떻게 만들어질건지 구조를 자세하게 생각해봐.”
    * **적용 내용:** AI가 제안한 로드맵을 바탕으로, 1차에서는 프로젝트명(str), 분야(str), 현재 진행률(int), 자료 개수(int), 중요도(float) 등을 입력받아 기초 준비도 점수를 계산하는 구조를 대략 계획하였다.

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**
이번 과제는 장기 프로젝트 관리와 포트폴리오 자료 저장을 동시에 수행하는 ‘프로젝트 볼트(Project Vault)’ 시스템 구현으로, 사용자로부터 프로젝트 정보를 입력받아 리스트에 저장하고, 가중치 연산을 통해 현재 프로젝트의 준비도와 상태를 분석하는 프로그램을 구축하는 것입니다. 특히 if-elif 조건문과 and/or 논리 연산자를 활용하여 프로젝트 상황에 맞는 상태 판정과 특별 칭호를 부여하는 분석 로직을 완성해야 합니다.

input()으로 프로젝트명, 분야, 현재 진행률, 저장한 자료 개수, 중요도, 최근 활동 공백일 수, 회고 작성 여부, 링크 등록 개수를 입력받아 하나의 리스트에 저장합니다.

가중치 공식을 적용하여 프로젝트 준비도 점수를 산출합니다.
준비도 점수 = 진행률 + (자료 개수 × 5) + (링크 개수 × 3) + 중요도 + 회고 보너스(회고 작성 시 +10)

if-elif-else를 사용하여 준비도 점수와 공백일 수를 기준으로 프로젝트 상태를 5단계로 판정합니다.
예를 들어, 준비도 점수가 매우 높으면 ‘순항’, 중간 수준이면 ‘진행 중’ 또는 ‘정체’, 낮으면 ‘위험’으로 분류하고, 최근 활동 공백이 7일 이상이면 점수와 무관하게 ‘휴면 프로젝트’로 판정하도록 설계합니다.

and/or 연산자를 활용하여 특별 칭호 부여 기능도 구현합니다.
예를 들어, 자료 개수와 링크 개수가 모두 많으면 ‘아카이브 마스터’, 진행률이 높고 공백일 수가 매우 적으면 ‘폭풍 성장 프로젝트’, 진행률·자료 개수·회고 작성 여부를 모두 만족하면 ‘포트폴리오 완성형’과 같은 칭호를 부여하도록 구현합니다.

현재 버전에서는 한 개의 프로젝트 정보를 리스트 형태로 저장하고 분석하지만, 이후에는 여러 프로젝트를 큰 리스트에 차곡차곡 저장하여 한 번에 관리할 수 있도록 확장할 예정입니다.
    
### **🤖 AI 파트너십 과정**
1. **내용 1: 프로젝트 볼트 컨셉 및 분석 로직 도출**
    * **프롬프트 요약:** “내가 제안한 장기 프로젝트 관리+포트폴리오 저장 프로그램인 프로젝트 볼트를 만들 건데, 리스트와 조건문을 활용해 재미있는 로직을 짜줘.”
    * **적용 내용:** AI가 제안한 방식에 따라 프로젝트 정보를 [프로젝트명, 분야, 진행률, 자료개수, 중요도, 공백일수, 회고작성여부, 링크개수] 형태의 리스트로 저장하고, 이를 바탕으로 준비도 점수를 계산하는 구조를 설계하였다. 또한 조건문을 이용해 프로젝트 상태를 ‘순항’, ‘진행 중’, ‘정체’, ‘위험’, ‘휴면 프로젝트’로 판정하고, 복합 조건을 만족할 경우 ‘아카이브 마스터’, ‘폭풍 성장 프로젝트’, ‘포트폴리오 완성형’과 같은 특별 칭호를 부여하는 아이디어를 실제 코드 설계에 반영하였다.

2. **내용 2: 효율적인 리스트 활용법 및 4단계 확장 로드맵 자문**
    * **프롬프트 요약:** “파이썬 기초 문법 단계(리스트 → 조건문 → 반복문 → 함수/딕셔너리)에 맞춰, 프로젝트 볼트 컨셉의 프로그램이 어떻게 발전할 수 있을지 4단계 기능 확장 로드맵을 제안해줘.”
    * **적용 내용:** AI의 제안을 바탕으로, 단순한 프로젝트 정보 입력을 넘어 ‘기초 프로젝트 카드 입력 및 준비도 계산(1차) → 리스트 저장 및 상태/칭호 판정(2차) → 무한 메뉴 기반 다중 프로젝트 관리 시스템 구축(3차) → 딕셔너리를 활용한 프로젝트 카드 구조화 및 함수 모듈화(4차)’로 이어지는 논리적인 기능 확장 로드맵을 확립하였다. 이를 통해 프로젝트 볼트가 단순 기록 프로그램이 아니라 실제 장기 프로젝트와 포트폴리오를 함께 관리하는 실용적인 소프트웨어가 되도록 방향을 잡았다.
    
### **🛠️ Troubleshooting & 기술 회고:**
1. **문제 1: 준비도 점수는 높지만 장기간 방치된 프로젝트가 ‘순항’으로 잘못 판정되는 현상**
    * **원인:** 조건문 작성 시 준비도 점수 기준을 먼저 검사하면, 공백일 수가 7일 이상인 프로젝트도 높은 점수 때문에 ‘순항’으로 먼저 분류되는 논리 오류가 발생했다.
    * **해결:** 공백일 수가 일정 기준 이상이면 가장 먼저 ‘휴면 프로젝트’로 판정하도록 조건문의 순서를 조정하여, 프로젝트 상태가 더 현실적으로 분석되도록 수정하였다.
2. **문제 2: 회고 작성 여부를 입력했는데 조건문이 제대로 동작하지 않는 현상**
    * **원인:** 사용자가 ‘예’, ‘yes’, ‘Y’, ‘y’처럼 서로 다른 형태로 입력할 수 있어서, 회고 작성 여부를 단순 문자열 비교만으로 처리하면 조건이 일치하지 않는 문제가 발생했다.
    * **해결:** 입력값을 소문자로 통일하거나 ‘예/아니오’를 미리 정한 형식으로 입력받도록 하여, 회고 작성 여부를 True/False처럼 명확하게 판별할 수 있도록 수정하였다.
